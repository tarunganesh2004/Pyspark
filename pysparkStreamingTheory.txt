Architecture:
pyspark uses micro batch processing (where in computations happen on small batches of data)

Spark Streaming Workflow
Spark discretizes (divides) the live streaming data in to small time bounded micro batches
Batch Interval is the parameter used to decide the size of each batch
Batch can be as small as one second to as big as multiple hours
Spark treats each batch of data as RDDs and processes them using RDD operations
Finally, the processed results of the RDD operations are returned as batches

Internally:
Data comes in micro-batches

Each micro-batch processed as a small batch job

Result appended to sink

This is called:

Micro-Batch Processing Model

Execution Flow:

Source → Logical Plan → Incremental Execution → Sink

Continuous streams of data get discretized into batches. Computations happen on each batch and output is also in the form of batches. Series of batches (RDDs) are typically called as Discretized Streams (DStreams).

DStreams
Discretized Stream (DStream) is defined as the fundamental abstraction available from Spark streaming
It is the data received from the source as continuous streams

 

As shown above,

DStream can be represented as a series of RDDs where each RDD is the data collected in a defined time interval
DStreams can be created by either applying high-level operations on other Dstreams or by using input data streams from the source
All operations that are applied on a DStream get translated into operations on the underlying RDDs
 

Receivers
Spark Streaming launches a Receiver for each input data source
Receivers are the tasks running in the specific application executors
Receivers collect the data from input data source and store it as RDD
Receivers replicate these RDDs for fault tolerance. Spark Streaming provides the way of managing lineage of RDDs which can be used to recompute in case of failures
For an application to receive data in parallel from various streams, multiple input DStreams can be created. This requires sufficient cores for processing the data received and to run the receivers.
 

Note: PySpark streaming libraries provide two ways of performing stream processing. Discretized Streams (DStream) and Structured Streaming. In this course, we will explore both of the APIs

Structured Streaming

Simplified real-time stream processing engine built on Spark SQL
Facilitates streaming computation similar to batch data processing
Consumed real-time structured data can be considered as unbounded table and SQL queries get executed incrementally in a continuous manner
Highly fault-tolerant and scalable
Supports low latency continuous processing model
Supports advanced operations like stream-to-batch joins and window event-time processing

output modes:
complete --complete modified/updated result table gets streamed to the output sink
append -- only the new rows appended to result table since the last trigger interval gets streamed to output sink
         applicable to the queries where already existing records in result table doesnt get modified
update -- only the updated rows appended to result table since the last trigger interval gets streamed to output sink ,
            only the modified rows gets written to the external storage
            if no aggregations in query,then this mode is equal to append

| Mode     | Use Case      | Meaning                   |
| -------- | ------------- | ------------------------- |
| append   | new rows only | Only new data             |
| update   | changed rows  | Only updated aggregations |
| complete | full result   | Entire table              |
